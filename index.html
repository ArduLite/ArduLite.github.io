ArduLite

Modern C++ Framework for Arduino AVR.

Beginner-friendly on the surface. Register-level underneath.

ArduLite is a lightweight, header-driven C++ framework for bare-metal AVR programming on the Arduino Uno, Nano, and Mega 2560. No pinMode, no digitalWrite, no hidden runtime — every call is designed to fold away at compile time into plain register access. New to microcontrollers? Start with Quick Start — you don't need to understand registers to use it.

Install ArduLite Read Quick Start View Source
Digital led(13, OUT);→sbi 0x04, 5DDRB |= 1<<5 — set as output
led.on();→sbi 0x05, 5PORTB |= 1<<5
led.off();→cbi 0x05, 5PORTB &= ~(1<<5)
led.toggle();→ldi r24,0x20 / out 0x03,r24write-1-to-PINB toggles PORTB, 2 cycles
led.read();→sbic 0x03, 5test PINB bit 5 directly

01 · Design Philosophy

Why ArduLite exists

The Arduino Core is friendly, but its abstractions — digitalWrite's pin lookup table, String's heap churn, delay()'s Timer0 dependency — cost cycles and bytes you don't always get to see. ArduLite is what you get if you rebuild the beginner-friendly vocabulary on nothing but avr-libc, and refuse anything that isn't zero-cost.

Goals

GoalHow ArduLite delivers it
Zero heapnew, malloc, std::vector, std::string are all off the table. Every object lives on the stack or in static storage with a size known at compile time.
Zero collisionArduLite never defines pinMode, digitalWrite, delay, millis, HIGH/LOW, or byte. It can be mixed into a project that still uses the Arduino Core without a single symbol clash.
Zero overheadPin-facing methods are marked always_inline. With a literal pin number, the whole lookup folds away at compile time into one sbi/cbi/sbic instruction — see the strip above.
Opt-in everythingThe master header only pulls in Digital, Analog, PWM and Utils. Timers, UART, SPI, I2C, interrupts and every component are separate headers you include only when you use them, so an unused peripheral is never initialized and never costs flash.

Explicit non-goals

ArduLite 1.x/2.x is scoped deliberately narrow. It does not attempt to support ESP8266, ESP32, STM32 or RP2040, and it does not ship WiFi, Bluetooth, Ethernet, MQTT, HTTP, OTA, or an RTOS. Those belong to separate projects built for those chips — bolting them onto an AVR-only, no-heap framework would break every guarantee above.

Who it's for. Students and teachers who want to see what a microcontroller is actually doing; makers and hobbyists who want Arduino-level readability without giving up register-level performance; embedded developers who want a sane starting point instead of writing raw avr/io.h by hand every time.

02 · Setup

Installation

Arduino IDE — via Library Manager (easiest)

  1. Open the Arduino IDE, then go to Sketch → Include Library → Manage Libraries… (or press Ctrl+Shift+I).
  2. Search for ArduLite in the Library Manager search box.
  3. Click Install on the ArduLite entry by Ajang Rahmat.
  4. Select Arduino Uno, Arduino Nano, or Arduino Mega 2560 under Tools → Board — ArduLite only targets these three.
  5. Include the master header in your sketch: #include <ArduLite.h>.

Arduino IDE — manual install

  1. Download the latest release archive from github.com/ArduLite/ArduLite.
  2. Extract it and rename the folder to ArduLite if needed, then place it inside your Arduino libraries directory (Documents/Arduino/libraries on most systems).
  3. Restart the Arduino IDE so it re-scans the libraries folder.
  4. Select your board and include ArduLite.h, same as above.

PlatformIO

Add it as a library dependency from the command line — PlatformIO fetches it straight from the GitHub repository, no manual copying needed.

terminal
# from inside your PlatformIO project folder
pio pkg install --library "https://github.com/ArduLite/ArduLite.git"

# or, for an older PlatformIO CLI version:
pio lib install "https://github.com/ArduLite/ArduLite.git"

Or add it directly to platformio.ini and let PlatformIO install it on the next build:

platformio.ini
[env:uno]
platform = atmelavr
board = uno
framework = arduino
lib_deps =
    https://github.com/ArduLite/ArduLite.git

; ArduLite does not need the Arduino framework at runtime, but PlatformIO's
; "arduino" framework is the simplest way to get an avr-gcc toolchain wired up.

Then run pio run to build, or pio run -t upload to build and flash.

No Arduino.h required. ArduLite sketches use a plain int main() entry point instead of setup()/loop(). If you're on the Arduino IDE, this still compiles fine — the IDE just needs one .ino file with a main() in it, which every ArduLite example provides.

03 · First Sketch

Quick Start

Three progressively richer examples: a blink, a PWM fade, and a sensor-driven brightness loop — the same three examples from the project README, shown here with a line-by-line breakdown.

1. Blink

Led_Blink.ino
#include <ArduLite.h>

int main() {
    Digital led(13, OUT);

    forever() {
        led.on();
        wait(1000);
        led.off();
        wait(1000);
    }
}

Digital led(13, OUT) configures pin 13 as an output once, at construction. forever() expands to while(1). wait(1000) blocks for 1000 ms using a calibrated _delay_loop_2 — no Timer0, no millis() dependency.

2. PWM fade

Led_PWM.ino
#include <ArduLite.h>

int main() {
    PWM led(9);

    forever() {
        for (uint8_t i = 0; i < 255; i++) { led.write(i); wait(5); }
        for (uint8_t i = 255; i > 0; i--) { led.write(i); wait(5); }
    }
}

3. Sensor-driven brightness

Analog_Read_Control_Led_Brightness.ino
#include <ArduLite.h>

int main() {
    PWM led(9);
    Analog sensor(A0);

    forever() {
        int sensorValue = sensor.read();
        float brightness = sensorValue * (255.0 / 1023.0);
        led.write(brightness);
    }
}

All three sketches are in examples/, importable directly from File → Examples → ArduLite in the Arduino IDE.

04 · Core Concepts

The zero-overhead model

Two techniques make this possible almost everywhere in ArduLite:

1. always_inline + compile-time constant pins

Every pin-facing helper (digitalWriteHigh, digitalTogglePin, ...) is marked __attribute__((always_inline)). Without it, GCC would leave the call as a real function at -Os, and the pin number would stop being a compile-time constant — forcing a runtime bit-shift to compute (1 << pin). With the attribute, and a literal pin like Digital led(13, OUT), the entire register lookup folds away and one method call becomes one AVR instruction.

2. Hardware toggle instead of read-modify-write

toggle() exploits a real AVR feature: writing a logic 1 to a bit in the PINx register flips that bit of PORTx, leaving every other bit untouched — 2 cycles, no read-modify-write race. Older chips without this feature (ATmega8/16/32) automatically fall back to PORTx ^= mask.

ArduLite callCompiles to (ATmega328P, literal pin)
Digital led(13, OUT)sbi 0x04, 5
led.on()sbi 0x05, 5
led.off()cbi 0x05, 5
led.read()sbic 0x03, 5
led.toggle()out 0x03, r24 (PINB write-1-to-toggle)
This only holds when the pin number is a literal or a constexpr. Passing a runtime variable as the pin still works correctly, but the compiler can no longer fold the branch chain, so you pay for the port lookup at runtime — the same trade-off you'd hit writing the register logic by hand.

Timer & resource map

ArduLite is careful never to let two modules fight over the same hardware timer. Know this map before combining modules in one sketch.

ResourceOwnerNotes
Timer0UntouchedReserved for the Arduino Core's own millis()/delay() if you ever mix them in — ArduLite never touches it.
Timer1PWM (pins 9/10 Uno), Servo, PulseDo not use Servo, Pulse, and PWM on pin 9/10 at the same time — they all reconfigure Timer1.
Timer2 — COMPATime / Timer / Stopwatch / Button / Interrupt debounceThe single 1 ms tick source (initTimer()), shared safely by every module that needs a clock.
Timer2 — COMPBcreateTimer() (TimerInterrupt)Only enabled when initTimerInterrupt()/createTimer() is actually called — a sketch that never uses it pays nothing.
ADCAnalogInitialized lazily on first read() call, AVcc reference, default prescaler 64.
TWI/I2C hardwarei2c global (ArduLiteI2C)Bit-rate register fixed at construction time (TWBR=72) — roughly 100 kHz at 16 MHz.
SPI hardwarespi global (ArduLiteSPI)Master mode only. The SS/CS pin is not managed automatically — pick it yourself via Digital.
UART hardwareuart / uart1..3 globalsMega 2560 exposes all four hardware UARTs; Uno/Nano only uart (UART0).
EEPROMeeprom global1024 bytes on ATmega328P, 4096 bytes on ATmega2560.

Core header — ArduLite.h

The master header is intentionally small. It defines short integer aliases, the forever() macro, and the two blocking-wait functions, then pulls in only Digital, Analog, PWM and Utils. Everything else is opt-in.

SymbolWhat it is
int8 / int16 / int32
uint8 / uint16 / uint32		Aliases for int8_t … uint32_t, in ArduLite's own naming style.
forever() { }Macro for while(1) { } — the main program loop, used instead of Arduino's loop() callback.
wait(uint32_t ms)Blocking millisecond delay. A real inline function, deliberately not a macro — a macro would rewrite every wait(...) substring across the whole program, including unrelated method names.
waitMicros(uint16_t us)Blocking microsecond delay, built on _delay_loop_2 (4 CPU cycles/iteration). One call covers up to ~16383 µs at 16 MHz.
wait()/waitMicros() never touch a timer — they're busy-loops calibrated purely from F_CPU. That means they can be called safely even before initTimer() has run, and they never collide with ArduLiteTime's Timer2-based clock.

Digital

src/ArduLiteDigital.h

Digital pin control with true zero-cost abstraction. Holds a single byte of RAM (the pin number) and nothing else — every method is always_inline.

Led_Toggle_With_Push_Button.ino (excerpt)
#include <ArduLite.h>

int main() {
    Digital button(2, IN);
    Digital led(13, OUT);
    button.pullUp();   // button wired to GND, no external resistor needed

    forever() {
        if (!button.read()) {   // active-low: pressed == LOW
            led.toggle();
            wait(300);          // crude debounce
        }
    }
}
Direction constants are the enum Direction { IN, OUT } — ArduLite's own vocabulary, never Arduino's INPUT/OUTPUT, so both can coexist in one project.

06 · Timing Reference

Time, Timer & Stopwatch

src/ArduLiteTime.h

ArduLite never defines millis(), micros() or delay() as free functions — that vocabulary lives inside objects (time.millis()) so it can never collide with the Arduino Core. Timer2 is the single 1 ms tick source shared by everything in this file, plus Button and Interrupt debounce.

Time — reads the running clock

Every method is static and the class holds no data — time costs no RAM and adds no call overhead beyond the read itself.

MethodDescription
time.millis()Milliseconds since the timer started. Wraps to 0 after ~49 days.
time.micros()Microseconds since start, 4 µs resolution @16 MHz. Wraps after ~71 minutes.
time.seconds()Whole seconds since start.
time.now()Alias for millis().
Time::wait(uint32_t ms)Blocking wait based on the Timer2 clock rather than a busy-loop — stays accurate even when ms comes from a variable.
Time::waitMicros(uint16_t us)Blocking microsecond wait, same underlying primitive as the core header's waitMicros().

Timer — non-blocking periodic task

9 bytes of RAM per instance. No interrupt, no callback — just a polled check you call from inside forever().

Constructor / MethodDescription
Timer(uint32_t intervalMs)Starts counting immediately from construction.
ready()Returns true exactly once each time the interval elapses. Advances by one interval rather than snapping to "now" — the rhythm doesn't drift, but resynchronizes automatically if it falls far behind.
reset()Restarts counting from the current time.
setInterval(ms)Changes the interval and restarts counting.
start() / stop()Pauses/resumes. ready() always returns false while stopped.
isRunning() constCurrent run state.
remaining() constMilliseconds left before the next ready() fires true.
Periodic_Task.ino
#include <ArduLite.h>
#include <ArduLiteTime.h>
#include <ArduLiteUART.h>

int main() {
    Digital led(13, OUT);
    Timer blink(250);    // fast task
    Timer report(1000);  // slow task, runs independently
    uart.begin(9600);

    uint16_t blinkCount = 0;

    forever() {
        if (blink.ready())  { led.toggle(); blinkCount++; }
        if (report.ready()) {
            uart.send("Uptime "); uart.send(time.seconds());
            uart.send(" seconds, blinks: "); uart.sendLine(blinkCount);
        }
    }
}

Stopwatch — measures a duration

MethodDescription
start()Starts, or resumes after stop().
stop()Pauses. The accumulated duration is kept.
reset()Back to zero, stopped.
restart()reset() then start() in one call.
elapsed() constTotal duration in milliseconds.
elapsedSeconds() constTotal duration in whole seconds.

uart.begin(9600);

if (i2c.probe(addr)) {
    uart.send("Device found at 0x");

Interrupt-driven command receiver

UART_Interrupt.ino
#include <ArduLite.h>
#include <ArduLiteLED.h>
#include <ArduLiteUART.h>

LED led(13);

bool strEqual(const char *a, const char *b) {
    while (*a && *a == *b) { a++; b++; }
    return *a == *b;
}

void onData(const char *line) {   // called from the RX ISR on every full line
    if (strEqual(line, "on"))     led.on();
    else if (strEqual(line, "off"))  led.off();
    else if (strEqual(line, "toggle")) led.toggle();
}

int main() {
    uart.begin(9600, onData);
    forever() { }   // main loop can stay empty — RX is fully interrupt-driven
}
The receive callback runs inside an ISR: keep it short, mark shared variables volatile, and never call wait() or send long messages from inside it. The internal line buffer is 16 bytes.

09 · Interrupts Reference

Interrupt (external)

src/ArduLiteInterrupt.h

Wraps AVR's two true external-interrupt lines (INT0/INT1), with optional built-in debounce timed off the Timer2 tick.

Uno / NanoINT0 = pin 2, INT1 = pin 3
Mega 2560INT0 = pin 21, INT1 = pin 20
ConstructorDescription
Interrupt(pin, callback, mode)No debounce. pin must be an INT0/INT1-capable pin.
Interrupt(pin, callback, mode, debounceDelayMs)Same, with a debounce window applied in the ISR itself.

mode maps to the AVR ISCn bits: 0 = LOW level, 1 = any logical CHANGE, 2 = FALLING edge, 3 = RISING edge.

Button_Interrupt.ino
volatile uint16_t pressCount = 0;
void onPress() { pressCount++; }

int main() {
    uart.begin(9600);
    Interrupt button(2, onPress, 3, 50);  // pin 2, RISING, 50 ms debounce

    forever() {
        // pressCount keeps incrementing in the background even while busy
    }
}

TimerInterrupt

src/ArduLiteTimerInterrupt.h

A scheduler for periodic callbacks that keep their rhythm even while the main loop is busy — the interrupt-driven counterpart to the polling Timer class. Runs on Timer2's COMPB unit, a separate compare channel from the 1 ms tick in ArduLiteTime.h, so the two never fight over one vector.

Uses Timer2 COMPB11 bytes RAM / slot
FunctionDescription
createTimer(intervalMs, callback)Registers a periodic task, auto-calling initTimerInterrupt() on first use. Returns a task ID, or TIMER_INVALID if all slots are full.
setTimerEnabled(id, bool)Enables/disables a task without removing it.
setTimerInterval(id, newInterval)Changes a task's period and restarts its count.

Slot count defaults to MAX_TIMERS = 4. Define #define MAX_TIMERS 8 before including the header to trade RAM for more slots.

Periodic_Task_Interrupt.ino (pattern)
Digital led(13, OUT);
void blink() { led.toggle(); }

int main() {
    createTimer(500, blink);   // calls blink() every 500 ms, automatically
    forever() { }                // free to do other work — blink keeps its rhythm
}
The callback runs inside an ISR: keep it minimal, mark shared state volatile, and never call wait() or send long UART messages from it.

Design rules (project conventions)

ArduLite's internal docs/rules.md spells out the constraints every module in this reference follows — useful context if you're extending the library yourself.

RuleDetail
C++ standardTarget C++17. Required: constexpr, inline, enum class, explicit constructors, const-correctness.
ForbiddenExceptions, RTTI, virtual inheritance, std::thread, std::filesystem, and any heap allocation (new/delete/malloc/calloc/realloc/free).
Avoidstd::string, std::vector — anything that hides a dynamic allocation.
API readabilityDigital led(13); led.on(); is the goal, not digitalWrite(13, HIGH);. Every API must read more clearly than the Arduino API it replaces.
Opt-in modulesNo optional module is auto-included in the master header. No peripheral is initialized unless the sketch actually uses it.
NamingClasses: PascalCase. Variables and methods: camelCase.

12 · For Beginners

Frequently asked questions

New to Arduino or embedded C++? Start here.

What is ArduLite, in plain terms?

It's a free library that lets you control an Arduino board with short, readable code like led.on() instead of the longer digitalWrite(13, HIGH) style — while producing code that is just as fast (often faster) than writing the registers by hand yourself.

Do I need to know what a "register" is to use it?

No. You can build complete projects — blink an LED, read a button, sweep a servo — using only the object methods shown in this reference, exactly like the Quick Start examples above. The register-level explanations in Zero-Overhead Model are optional background reading for when you're curious how it works under the hood.

Which Arduino board should I use with ArduLite?

Any Arduino Uno or Nano is the easiest starting point — they're the cheapest, most common boards and every example in this documentation works on them unmodified. Use a Mega 2560 only if your project needs more pins or more than one hardware serial port.

How is this different from just using the normal Arduino language?

You don't have to choose — see the ArduLite vs. Arduino Core table. ArduLite never redefines Arduino's own functions, so you can use both in the same sketch if a library you need still expects the standard Arduino API.

I'm stuck — where do I start?

Read Installation, copy the first example from Quick Start exactly as written, upload it, and confirm the LED blinks before changing anything. Then open Examples Index and pick the next one closest to what you want to build.
